# PULL Call Diagnosis

Use this reference when reviewing a sales call transcript to diagnose whether the buyer had real demand-side pull (Project, Unavoidable, List of options with Limitations) and whether the seller surfaced it effectively.

**Framework source:** PULL framework, Rob Snyder. See "The Power of Pull" or "The Physics of Startups" newsletter for full methodology.

## The PULL Framework

**Project (P):** What is the buyer trying to accomplish? Not a vague goal ("improve pipeline"), but an actionable project ("migrate to new CRM by Q2 2025").

**Unavoidable (U):** Why would it be weird if they didn't do this project? What forces it? Board pressure, contract deadline, competitive threat, new hire demands it, customer will leave without it.

**List of Options + Limitations (L+L):** What have they tried or considered? What's broken about each option?

**The structure:** PULL is ONE integrated situation. U only exists if P is clear. L+L only makes sense given the specific P. If the buyer names three different projects, one P is the real one driving urgency; the others are nice-to-haves.

## Diagnosis Template

### 1. Extract All Projects Mentioned

List every plausible project the buyer named or implied, in their voice (not your summary):

```
Project 1: "We need to consolidate three CRMs into one"
Project 2: "Our team is growing and current reporting breaks at 20 people"
Project 3: "We're losing deals because forecast credibility is low"
```

### 2. Select the Likely PULL Project

Which one forced the conversation? Which would be weird to ignore?

```
PULL Project: "We're losing deals because forecast credibility is low"
Reason: The buyer mentioned this twice unprompted. Other projects were mentioned in passing ("...and also reporting...").
```

### 3. Diagnose the Full PULL

| Component | Evidence from Call | Filled? |
|---|---|---|
| **P: Project** | "We're losing deals because forecast credibility is low" | YES |
| **U: Unavoidable** | "Board is asking why we missed last quarter's forecast. CEO wants to know the real number." | YES |
| **L: List** | "We tried [tool X], but it doesn't integrate with [system Y]. We built custom [spreadsheet], but it breaks when sales forgets to update." | YES |
| **L: Limitations** | Tool X = no integration. Spreadsheet = manual, breaks on adoption. Doing nothing = keep missing forecast and lose credibility. | YES |

**Verdict:** PULL is visible. All four components cohere around one situation: they need forecast accuracy to keep the board/CEO happy, and their current options (tool + spreadsheet + status quo) all fail.

### 4. Seller Performance Assessment

Did the seller test for PULL or just listen politely?

**Testing for PULL:**
- Asked "Why is forecast accuracy important right now?" (testing unavoidability)
- Said "What have you tried that didn't work?" (testing limitations)
- Mirrored it back: "So you need forecast accuracy by [timeline], and you've tried tool X and the spreadsheet." (confirming understanding)

**Only listening (not testing):**
- Accepted first answer without probing
- Moved to pitch before confirming unavoidability
- Never asked "What have you tried?"

### 5. Pitch Fit

Did the seller's solution directly address the PULL?

```
Seller's pitch: "Our platform integrates with [system Y] and auto-syncs stage data."

Does it fit?
- Addresses Project? YES (forecast accuracy, because real data)
- Resolves Limitation 1 (tool X no integration)? YES
- Resolves Limitation 2 (spreadsheet breaks)? YES
- Explains why you specifically? YES (integration point they named as blocker)

Fit: GOOD. The pitch was surgical. Only mentioned what mattered.
```

### 6. Red Flags

| Flag | Meaning | Example |
|---|---|---|
| **No PULL found** | Buyer talked about interests, not forces. Conversation is exploratory, not urgent. | "We should probably look into better forecasting someday." |
| **Multiple PULL candidates** | Buyer named 3 different projects with equal urgency. Which is real? | "We need forecast, reporting, and pipeline hygiene... all equally critical." (Likely: one is real, two are nice-to-haves masquerading as forced decisions.) |
| **U missing** | Project is clear but no forcing event. Buyer could delay indefinitely. | "We want better forecast. Budget cycle is next quarter, so maybe Q2." (Not unavoidable; no board pressure, no deadline forcing now.) |
| **Seller over-pitched** | Seller mentioned capabilities buyer didn't ask for. | Seller described 5 features; buyer asked about 1. (Over-pitch signals seller didn't diagnose; fishing for what might stick.) |
| **Seller avoided objections** | When buyer said "Your tool doesn't integrate with [system]," seller changed subject. | Seller didn't address the specific Limitation buyer named. Deal will stall when buyer re-evaluates. |

## Worked Example: Good PULL Diagnosis

**Call snippet:**

Buyer: "We've been missing forecast for two quarters. Board asked in last meeting why we can't predict our own pipeline."

Seller: "That sounds like real pressure. What's the cost of missing forecast?"

Buyer: "Jobs at stake at the ops level. CEO doesn't trust the number anymore."

Seller: "When do you need to have this fixed?"

Buyer: "Next quarter. We're presenting to the board again in April."

Seller: "April. So it's not theoretical. What have you tried?"

Buyer: "We bought [tool X] last year. It doesn't talk to [system Y], so we can't auto-sync, so forecast is manual. We also use a spreadsheet for [department], but it's out of date before we send it."

Seller: "So tool X fails because of the integration gap. Spreadsheet fails because it's manual and breaks on adoption. Doing nothing means April board call is just as bad."

Buyer: "Exactly. We need integration, and it needs to be stable."

**Diagnosis:**

| Component | Evidence |
|---|---|
| **P: Project** | Fix forecast accuracy; present credible number to board in April |
| **U: Unavoidable** | Board pressure, jobs at risk, CEO lost trust, hard deadline (April) |
| **L+L** | Tool X = no integration. Spreadsheet = manual + breaks. Status quo = same problem. |
| **Seller testing** | Asked cost ("what's the cost"), timing ("when"), and Limitations ("what have you tried?") |
| **Seller pitch opportunity** | Next message should be: "Integration + stable automation is what you need. Here's how we fit that gap." |
| **Verdict** | PULL is visible and well-diagnosed. Seller is positioned for fit. |

## What Good Diagnosis Looks Like

- Every component of PULL (P, U, L+L) is backed by a direct quote from the call.
- Seller tested for PULL, not just listened.
- Pitch was surgical: only mentioned capabilities that resolved stated Limitations.
- No red flags (multiple PULL candidates, missing U, over-pitch, objections avoided).
- You can re-listen to the call and verify every claim.

The mediocre version:
- Summarises PULL vaguely ("They need better forecast").
- Uses paraphrase instead of quotes.
- Ignores what the seller avoided asking.
- Treats all buyer interests as equal priority.
